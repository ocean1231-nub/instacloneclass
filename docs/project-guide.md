# 인스타그램 클론 프로젝트 안내

## 목표

고등학생이 3회차에 걸쳐 모바일 화면 중심의 소셜 앱을 만든다. React + Vite 화면, FastAPI 서버(uv), SQLite + SQLAlchemy를 사용한다. 가입·로그인, 사진 게시, 좋아요·댓글, 프로필 꾸미기, 라이트·다크 모드가 필수다. 팔로우와 DM은 시간이 남으면 만드는 선택 기능이다. 제공된 01~09 캡처를 화면 참고 자료로 활용한다.

## 3회차 학습 계획

| 회차 | 목표 | 마무리 확인 |
|---|---|---|
| 1회차 | 화면 구조와 모바일 레이아웃, React 컴포넌트와 화면 이동, 가입·로그인 화면과 피드 목업, 라이트·다크 모드 | 휴대폰 폭에서 주요 화면과 테마 전환을 확인할 수 있다 |
| 2회차 | FastAPI·SQLite 연결, 가입·로그인, 게시물 사진 업로드, 피드, 좋아요·댓글, 프로필 수정 | 로컬에서 가입부터 게시물·댓글 작성까지 데이터가 남는다 |
| 3회차 | 기능 연결과 오류 수정, 배포 준비·배포, 실제 휴대폰으로 검증. 여유가 있으면 팔로우 또는 DM | 인터넷 주소로 접속해 필수 흐름과 저장 유지 확인 |

회차 길이와 학생 경험에 따라 난이도가 높을 수 있으므로 교사는 Python·Node·uv 환경과 호스팅 계정을 미리 준비한다. 시간 부족 시 선택 기능과 탐색·릴스 화면을 생략하고 필수 흐름부터 완성한다.

## 권장 폴더 구성

`frontend/`는 React 화면, `backend/`는 FastAPI·DB 모델과 업로드 처리, `docs/`는 명세를 둔다. 현재 제공된 캡처는 `instagram-clone-handout/`에 보관한다. 비밀번호, 토큰, 실제 DB와 업로드 사진을 공개 저장소에 올리지 않는다. 환경 변수 이름과 예시만 별도로 기록한다.

## 배포 계획

프론트엔드는 무료 정적 웹 호스팅, 백엔드는 Python 실행과 HTTPS를 지원하는 호스팅에 배포한다. 구체적인 서비스는 수업 시점의 무료 요금제와 조건을 확인해 선택한다. **서버의 SQLite DB 파일과 업로드 사진을 모두 유지할 영구 저장소가 반드시 필요하다.** 무료 서비스가 영구 디스크를 제공하지 않으면 재배포 시 데이터가 사라질 수 있으므로, 영구 저장소가 있는 호스팅을 선택하거나 교사가 외부 DB·파일 저장소로의 변경을 별도로 준비한다. SQLite를 고수한다면 영구 디스크가 있는 실행 환경이 필요하다. 무료 제공 여부와 절전·용량 제한은 배포 전에 확인한다.

1. 선생님이 영구 저장소, HTTPS, Python 실행 지원과 비용을 사전 확인한다.
2. 백엔드에 DB·업로드 경로와 토큰 비밀값, 프론트엔드 주소를 설정하고 배포한다.
3. 프론트엔드에 백엔드 API 주소를 설정하고 빌드·배포한다.
4. 서버 CORS를 실제 프론트엔드 주소에 맞추고 공개 URL에서 확인한다.
5. 서버를 재시작하거나 재배포한 뒤 계정·게시물·사진이 유지되는지 확인한다.

## 최종 점검

- 휴대폰에서 가로 스크롤 없이 가입·로그인·로그아웃을 할 수 있다.
- 라이트·다크·기기 설정 따르기 전환이 작동하고 새로고침 후 선택이 유지된다.
- 사진 게시, 피드 조회, 좋아요 추가·취소, 댓글 작성, 프로필 수정이 된다.
- 다른 사용자의 글을 삭제할 수 없고, 중복 사용자 이름과 잘못된 로그인은 안내된다.
- 새로고침 및 서버 재시작 후 DB와 업로드 사진이 남는다.
- 배포된 프론트엔드와 API가 HTTPS로 통신하고 실제 휴대폰에서 동작한다.

구체적인 화면, API, 데이터 구조는 각각 `frontend.md`, `backend.md`, `database.md`를 따른다.
